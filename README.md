# ConturAI

**ConturAI** — полностью локальный корпоративный AI-ассистент с поддержкой RAG (Retrieval-Augmented Generation). Система объединяет современный веб-интерфейс, высокопроизводительный инференс больших языковых моделей через **vLLM** и продвинутый гибридный поиск на базе **PostgreSQL (pgvector)**.

Работает автономно, без доступа к интернету (после скачивания моделей). Поддерживает извлечение текста и таблиц из PDF, DOCX и XLSX.

## Ключевые возможности

### Инфраструктура и Бэкенд
- **Единая база данных:** PostgreSQL с расширением `pgvector` (HNSW-индекс) используется как для хранения бизнес-данных, так и для векторного поиска.
- **vLLM:** Высокопроизводительный инференс LLM с OpenAI-совместимым API. Поддержка GPU NVIDIA (CUDA), AMD (ROCm) и CPU.
- **Асинхронность:** FastAPI + SQLAlchemy 2.0 async + asyncpg для высокой пропускной способности.
- **Гибридный поиск (RAG):** Комбинация векторного поиска (по смыслу) и полнотекстового поиска (BM25 по `tsvector`). Результаты объединяются через Reciprocal Rank Fusion (RRF) и пересортировываются Cross-Encoder'ом (Reranker) для максимальной точности.
- **Умный парсинг:** Извлечение текста и таблиц из PDF/DOCX/XLSX (с фолбэком на OCR).
- **Динамические настройки:** Параметры генерации, RAG и системные промты хранятся в БД и меняются на лету.
- **Шифрование секретов:** API-ключи и чувствительные настройки в БД хранятся в зашифрованном виде (Fernet).

### Фронтенд и UX
- **Современный интерфейс:** React 18, TypeScript, Vite, Tailwind CSS.
- **Стриминг ответов (SSE):** Нейросеть отвечает в режиме реального времени, как в ChatGPT. Пользователь может переключать режим (стриминг / полный ответ) прямо в чате.
- **Рендеринг Markdown:** Полная поддержка таблиц (`remark-gfm`) с умной очисткой от лишних оберток.
- **Модульный API-клиент:** Централизованная обработка ошибок и Toast-уведомления (вместо `alert`).

### Безопасность и Администрирование
- **RBAC (Ролевая модель):** Разделение прав на `admin`, `editor` и `user`.
- **Журнал аудита:** Логирование всех критичных действий (входы, загрузка/удаление файлов, смена настроек) с указанием IP.
- **Управление доступом к файлам и чатам:** Пользователи не могут скачать оригинал документа или историю чата без одобрения администратора (система заявок).
- **Мониторинг:** Встроенная панель отслеживания нагрузки на CPU, RAM, диск и GPU (NVIDIA/AMD). Плюс статистика LLM (токены, скорость генерации).
- **Резервное копирование:** Создание и скачивание бэкапов БД и загруженных файлов прямо из веб-интерфейса.
- **Теги:** Справочник тегов, который наполняет админ. Пользователи выбирают теги для фильтрации поиска по документам.
- **База знаний (Few-Shot):** Добавление эталонных пар "Вопрос-Ответ" для повышения качества ответов без дообучения модели.

## Технологический стек

- **Backend:** Python 3.12, FastAPI, SQLAlchemy (async), `uv` (менеджер пакетов).
- **Frontend:** React 18, TypeScript, Vite, Tailwind CSS.
- **БД:** PostgreSQL 16 + pgvector (HNSW).
- **LLM:** vLLM (NVIDIA / AMD / CPU).
- **Embeddings & Reranker:** SentenceTransformers (`multilingual-e5-large`, `bge-reranker-v2-m3`).
- **Инфраструктура:** Docker, Docker Compose.

## Архитектура

- **Frontend (React/TS)** - отвечает за интерфейс и взаимодействие с пользователем.
- **Backend (FastAPI)** - принимает запросы, управляет базой данных и оркестрирует работу RAG.
- **vLLM** - генерация ответов (OpenAI-совместимый API).
- **PostgreSQL + pgvector** - хранение пользователей, документов и векторных эмбеддингов.

## Требования

- **Docker** (версия 24+) и **Docker Compose** (v2).
- **Python 3.12+** (опционально, только для запуска установщика и тестов).
- Оборудование:
  - **NVIDIA GPU** (>= 8 ГБ VRAM для 1.5B модели).
  - **AMD GPU** с установленным ROCm 6.1+ (>= 16 ГБ VRAM для 3B модели).
  - **CPU** (>= 8 ГБ ОЗУ, медленно, только для тестов).

Установщик спросит:

**Модель (влияет на VRAM и качество):**

| № | Модель | VRAM | Рекомендация |
|---|---|---|---|
| 1 | Qwen2.5-0.5B | ~1 ГБ | слабый ПК / CPU |

## Управление

Все команды выполняются из корня проекта.

```bash
# Сброс пароля администратора
docker compose exec backend python scripts/manage.py reset-admin

# Скачать модели (пропускает уже скачанные)
docker compose exec backend python scripts/manage.py download-models

# Перекачать модели
docker compose exec backend python scripts/manage.py download-models --force

# Переиндексировать документы (если сменили модель эмбеддингов)
docker compose exec backend python scripts/manage.py reembed

# Создать бэкап БД и файлов
docker compose exec backend python scripts/manage.py backup

# Посмотреть логи
docker compose logs -f backend vllm

# Пересобрать после правок кода
docker compose up -d --build backend
```

## Админ-панель

Открыв `http://localhost:3000/admin` (под учетной записью администратора), вы получите доступ к разделам:

- **Пользователи** — создание, блокировка, смена ролей (admin/editor/user), корзина.
- **Промты** — `system_prompt`, `user_prompt` с подсказками по доступным переменным.
- **Параметры LLM** — temperature, top_p, top_k, penalties, seed, лимиты RAG. Изменения применяются на лету.
- **Документы** — загрузка файлов, выбор тегов, скачивание оригиналов (по запросу), удаление.
- **Теги** — создание цветных тегов для категоризации документов.
- **Запросы на скачивание** — одобрение заявок на скачивание файлов и чатов.
- **Корзина чатов** — восстановление или безвозвратное удаление чатов.
- **База знаний (Few-Shot)** — добавление идеальных ответов на частые вопросы.
- **Журнал событий** — аудит действий пользователей.
- **Базы данных** — создание и скачивание резервных копий.
- **Мониторинг** — графики CPU, RAM, дисков, GPU и статистика токенов LLM.

## Troubleshooting

**Read-only file system при скачивании моделей**
Том `./models` для сервиса `backend` должен быть без `:ro`. Для `vllm` — с `:ro` (он только читает).

**password authentication failed**
Пароль в `.env` не совпадает с `pgdata`. Полная переустановка:

```bash
docker compose down -v
./install.sh
```

**Connection error в чате**
vLLM не успел загрузить модель. Проверить:

```bash
docker compose ps vllm
docker compose logs --tail=50 vllm
```
На CPU загрузка занимает 1–3 минуты.

**Failed to fetch на фронтенде**
Бэкенд перезагружается (например, применяются миграции). Подождите 10–15 секунд. Если не проходит, проверьте `docker compose logs backend`.

## Миграция с версии 1.x (Ragi_AI)

**Внимание!** Прямая миграция данных с версии 1.x (Ragi_AI) на 2.0 **невозможна**. 

Архитектура проекта была полностью переписана:
- Qdrant заменен на PostgreSQL (pgvector).
- Ollama заменен на vLLM.

Для перехода на новую версию требуется чистая установка. Вам будет необходимо заново загрузить все документы и настроить параметры через админ-панель.
